**Security: Bearer token exposed via process argv on the target Linux host**

`render_installer_sh` passes the caller's session token to `curl` via `-H` (line 497), putting the full `Authorization: Bearer <token>` header on the process's command line. `/proc/<pid>/cmdline` (what `ps aux` reads) is world-readable by default on Linux, unlike `/proc/<pid>/environ` (owner/root-only) — so any other local user on the target machine can capture the token during the curl invocation window. That's new exposure this PR introduces: the existing manual browser-download flow never puts the token on a command line at all.

Notably, `render_install_sh` just below (line 781, `export KANADE_NATS_TOKEN=...`) already avoids exactly this problem for the NATS token by using an env var instead of a flag. The same treatment (or `curl -K -` reading `header = "Authorization: Bearer ..."` from stdin) would close the gap here too.

The token is short-lived (expires with the session, per the script's own warning), so the window is narrow, but on shared/multi-tenant boxes this is a real local info-disclosure worth closing, or at minimum calling out next to the existing "treat it like a password" warning.
